# HB Quiz — Live Quiz Board

Живое игровое поле для офлайн-квиза в формате «Своя игра»: 6 категорий × 6 номиналов (100–600).
Ведущий управляет полем с ноутбука, игроки смотрят его на телефонах или ТВ, и любое изменение
синхронизируется за доли секунды.

Кнопок ответа, таймеров и подсчёта очков здесь нет: игра идёт вживую с физическими кнопками.

**Стек:** React + Vite + TypeScript, Firebase Firestore, Firebase Anonymous Auth, Framer Motion,
Lucide, GitHub Pages. Собственного backend нет.

---

## Как это работает

| Маршрут | Кто | Что делает |
| --- | --- | --- |
| `#/` | все | Главная: «Я ведущий» или вход по коду комнаты |
| `#/host` | ведущий | Создать комнату, список своих комнат в этом браузере |
| `#/host/:roomId` | ведущий | Управление полем, вопросы, ответы, сброс, QR-код |
| `#/room/:roomId` | игроки | Поле в реальном времени, только чтение |

**Статусы карточек:** `available` (доступна), `opened` (разыгрывается), `completed` (использована: затемнена и перечёркнута).

**Сценарий ведущего:**
1. «Создать комнату», затем «Редактировать»: переименуйте категории в заголовках и нажимайте на карточки,
   чтобы ввести вопрос и ответ. Кнопка «Сохранить и далее» сразу переходит к следующей карточке.
2. Нажмите «Готово», затем «QR-код» или «Копировать ссылку» и отправьте ссылку игрокам.
3. Нажатие на карточку открывает её (`opened`), у игроков она подсвечивается. Вопрос появляется в модальном окне,
   ответ скрыт за кнопкой «Показать ответ».
4. «Завершить вопрос» переводит карточку в `completed` у всех. «Вернуть в доступные» отменяет случайное нажатие.
   Использованную карточку можно «Открыть снова».
5. «Сброс» после подтверждения делает все 36 карточек доступными. Категории и вопросы сохраняются.

Кнопка ⤢ включает полноэкранный режим: поле растягивается на весь экран (подходит для ТВ и проектора).

## Вопросы по умолчанию

Каждая новая комната сразу создаётся с темами и вопросами из `BIRTHDAY.md` в корне проекта: 6 тем × 6 вопросов,
ответ и курсивная подсказка для ведущего. Чтобы поменять набор для всех будущих комнат, отредактируйте этот файл
в том же формате (`## N. Тема` → `**100.** Вопрос` → `> **Ответ**`). Уже созданные комнаты не меняются.
Заменить вопросы в одной комнате можно через окно QR-кода → «Импорт вопросов».

Набор собирается в отдельный файл сайта и загружается только при создании комнаты, после пароля ведущего.
Браузеры игроков его не скачивают. Но это обычный статический файл: человек, который специально полезет
в файлы сайта, сможет его найти.

`BIRTHDAY.md` **не хранится в репозитории** (он в `.gitignore`), чтобы ответы не лежали в публичном коде.
Локально файл лежит в корне проекта. При сборке на GitHub Actions он создаётся из секрета `BIRTHDAY_MD`.
Чтобы поменять вопросы на сайте, обновите этот секрет и перезапустите деплой.

## Команды и табло

- Команд две. Их названия редактируются прямо на табло: нажмите на имя, введите новое и нажмите Enter.
- В открытом вопросе ведущий выбирает «Кому засчитать?»: одну из команд (её счёт растёт на номинал вопроса)
  или «Никому». Карточка сразу закрывается у всех игроков.
- У использованной карточки можно поменять, кому засчитаны очки. «Вернуть в доступные» снимает очки за неё.
- Счёт — сумма номиналов засчитанных команде карточек. «Сброс» обнуляет счёт, названия команд сохраняются.
- **Табло видит только ведущий.** Названия команд и очки лежат в приватном документе `private/content`,
  который правила Firestore не дают прочитать игрокам. Если включить полный экран, например для вывода на ТВ,
  табло и отметки команд на карточках скрываются.

## Пароль ведущего

Страницы `#/host` и `#/host/:roomId` открываются только после ввода пароля ведущего. Пароль спрашивается
при каждом открытии и каждой перезагрузке страницы. Нигде не запоминается: переходы внутри панели
(создание комнаты → поле) не требуют повторного ввода. Экран игроков пароля не требует.

- В коде хранится не сам пароль, а его SHA-256 ([`src/components/HostGate.tsx`](src/components/HostGate.tsx)).
- Сменить пароль без правки кода: задайте `VITE_HOST_PASSWORD_SHA256` (в `.env` и в Secrets GitHub)
  значением `printf '%s' НОВЫЙ_ПАРОЛЬ | shasum -a 256`.
- Это барьер в интерфейсе, а не криптографическая защита. Сайт статический, и 6-значный пароль можно подобрать
  по хешу из кода. Защиту данных по-прежнему обеспечивают `firestore.rules`: менять комнату может только её создатель.

## Модель данных и безопасность

```
hbquiz_rooms/{roomId}                      ← публичный документ, его читают игроки
  hostUid: string                   ← Firebase Auth UID создателя
  categories: string[6]
  cards: { c0_100: "available" | "opened" | "completed", … 36 ключей }
  createdAt, updatedAt: timestamp

hbquiz_rooms/{roomId}/private/content      ← только для ведущего
  questions: { c0_100: { question, answer }, … }
```

Правила [`firestore.rules`](firestore.rules):

- читать комнату может любой анонимно вошедший пользователь, но только по точному ID
  (`list` запрещён, поэтому перебрать комнаты нельзя);
- создавать комнату можно только с `hostUid == auth.uid`, а ID должен иметь формат 12 символов;
- изменять комнату может только её создатель: `hostUid` и `createdAt` менять нельзя, допустимы только
  разрешённые поля, 6 категорий и 36 карточек с валидными статусами. Записать в публичный документ ответ или
  любое другое поле нельзя;
- `private/content` (вопросы и ответы) читает и пишет только создатель комнаты;
- всё остальное в базе закрыто.

ID комнаты состоит из 12 случайных символов (`crypto.getRandomValues`, ≈ 59 бит энтропии, без похожих
символов 0/O/1/I/L). Admin SDK и секретные ключи не используются: web-конфиг Firebase — это публичные
идентификаторы, а доступ ограничивают правила.

> ⚠️ **Ограничение анонимного входа.** Права ведущего привязаны к анонимному UID конкретного браузера.
> В другом браузере, в режиме инкогнито или после очистки данных сайта управлять комнатой уже не получится,
> хотя игроки по-прежнему будут видеть поле. Приложение предупреждает об этом на экране ведущего.
> Проводите игру с того же устройства, где создали комнату.

Устойчивость к сети: Firestore работает с локальным кешем (`persistentLocalCache`). При потере интернета поле
остаётся на экране, действия ведущего применяются сразу и уходят на сервер после переподключения, которое
происходит автоматически. Индикатор в шапке показывает «Онлайн», «Подключение…» или «Нет сети».

## 1. Настройка Firebase

1. Откройте [Firebase Console](https://console.firebase.google.com/) и создайте проект (Google Analytics не нужен).
2. **Build → Authentication → Get started → Sign-in method → Anonymous → Enable.**
3. **Build → Firestore Database → Create database** (production mode, ближайший регион).
4. **Firestore → Rules:** вставьте содержимое `firestore.rules` и нажмите **Publish**.
   Либо через CLI: `npx firebase-tools deploy --only firestore:rules --project <project-id>`.
5. **Project settings → General → Your apps → Web (`</>`)**: зарегистрируйте приложение и скопируйте `firebaseConfig`.
6. **Authentication → Settings → Authorized domains:** добавьте `<ваш-логин>.github.io`.

## 2. Локальный запуск

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env      # заполните значения из firebaseConfig
npm run dev               # http://localhost:5173
```

```bash
npm run build             # проверка типов + production-сборка в dist/
npm run preview           # локальный просмотр сборки
```

Чтобы проверить игру с телефонами в локальной сети, запустите `npm run dev -- --host` и откройте адрес
`http://<IP-ноутбука>:5173` (IP также нужно добавить в Authorized domains).

### Эмулятор Firebase (необязательно)

Для разработки без реального проекта нужны firebase-tools и **JDK 21+**:

```bash
npm run emulators         # Auth :9099 + Firestore :8080
```

В `.env` раскомментируйте блок `demo-hb-quiz` из `.env.example` (`VITE_USE_FIREBASE_EMULATORS=true`).

Автотест правил безопасности и синхронизации (хост/игрок, запреты, задержка доставки):

```bash
npm run test:rules
```

## 3. Публикация на GitHub Pages

1. Создайте репозиторий и запушьте код в ветку `main`.
2. **Settings → Secrets and variables → Actions → New repository secret:** добавьте шесть секретов
   с теми же именами, что в `.env.example`:
   `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
   `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_APP_ID`.
   И седьмой секрет `BIRTHDAY_MD`, в который вставлено всё содержимое файла `BIRTHDAY.md`.
3. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
4. Каждый push в `main` запускает `.github/workflows/deploy.yml`, который собирает и публикует сайт.
   Ручной запуск: **Actions → Deploy to GitHub Pages → Run workflow**.
5. Сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.

Почему ссылки работают на Pages: используется `HashRouter` (маршруты после `#/`), а в Vite задан
относительный `base: './'`. Поэтому сборка работает из любой подпапки и на собственном домене, а ссылка-приглашение
вида `https://<логин>.github.io/<репо>/#/room/ABCD…` открывается напрямую без 404.
При необходимости `base` можно переопределить переменной `VITE_BASE`.
